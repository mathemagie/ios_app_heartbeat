01

The idea, in one breath

A heartbeat is private, internal, invisible. Heart Nebula takes that hidden signal and pushes it out into the world as something everyone can watch in real time.

The in-ear PPG sensor on AirPods Pro 3 — or the optical sensor on an Apple Watch — reads your beats per minute. The number leaves your phone, crosses the internet, and lands as a living visual: a nebula that pulses on every beat, beating now, not on a recording. When your heart speeds up, so does the star.

02

The mental model

Think of it as a relay race for one number. The baton is your current BPM. It's handed off four times — phone, cloud function, broadcast network, browser — and each runner only does one small, honest job.

Two ideas make the whole thing safe and simple. First: the phone never talks to the broadcast network directly — a tiny server stands in the middle and keeps the one secret that could be abused. Second: the stream is public and one-way. The browser only ever listens; it can't push anything back. That's why the page can be a flat, buildless HTML file with nothing to leak.

04

The four moving parts

Each piece is small on purpose. Here's what each one owns.

Capture

iOS app

SwiftUI app that reads Health data and forwards it.

  • HealthKitManager — anchored queries fetch only new beats
  • HeartRateStreamer — feeds the UI and the publisher
  • PusherService — rate-limited POST to the cloud
Gatekeep

Vercel function

A few lines of Python that validate and re-broadcast.

  • /api/heartbeat — checks BPM, triggers the event
  • /api/config — hands the browser the public key only
  • The Pusher secret lives here, never in the client
Broadcast

Pusher Channels

The real-time backbone.

  • Channel heartrate-live, event heartrate-update
  • Public & one-way — clients subscribe, never publish
  • WebSocket fan-out to unlimited viewers
Render

Web nebula

One HTML file. No framework, no build.

  • index.html — the breathing visualization
  • nebula.js — pure helpers, also unit-tested in Node
  • Optional synthesized lub-dub heartbeat sound
05

Making pixels beat like a heart

A real heartbeat isn't a single thump — it's lub-dub: a strong systolic squeeze, then a softer diastolic one. The nebula copies that shape exactly. The whole trick is turning a BPM number into the length of one animation cycle: 

// one cardiac cycle, in seconds
const period = 60 / bpm;          // 62 BPM → 0.97 s per beat
orb.style.animationDuration = period + "s";

// the two-peak pulse, as CSS keyframes
@keyframes pulse {
  0%   { transform: scale(1);     }
  14%  { transform: scale(1.085); } /* lub — systole  */
  34%  { transform: scale(1.05);  } /* dub — diastole */
  48%  { transform: scale(1);     }
  100% { transform: scale(1);     } /* rest until next */
}

Because the duration is recomputed on every reading, the star is always locked to your live rate. The same curve drives brightness, saturation, hue and scale at once — so the nebula doesn't just pulse, it glows on the beat.

Why a buildless file? The browser only listens to a public stream and animates with CSS. There's no state to protect and nothing to compile — so the whole client is a single file you can read top to bottom.
06

Privacy & the honest secret

Heart-rate data is personal, so the design is deliberately careful:

  • Health data is read only with your explicit permission, and only the BPM number leaves the phone — no names, no identity.
  • The Pusher secret lives only on the server; the browser receives just the public key, so it can listen but never broadcast.
  • The server rejects bogus values (anything outside 20–300 BPM) before anything is published.
  • The stream is a public capability link: anyone with the URL can watch the beat, so treat the address like a key.
